How to review what an AI agent did and approve it from anywhere

The bottleneck in agent work has moved. It is not whether the model can do the task; it is whether you can tell what it did, and whether you can answer it at the moment it stops to ask.

The three layers of review

The diff. What changed. Cheap, precise, and the place to start every time. It tells you nothing about what the agent tried and abandoned, or why it made a choice.

The transcript. What it was thinking, what it ran, what came back. Worth searching rather than reading. Go to it when the diff contains something you did not expect.

The live session. What it is doing right now. The only layer that lets you intervene before a bad decision lands rather than after. Also the only one most setups do not have when the person is away from the desk.

Approval fatigue is a scoping problem

If you are approving prompts faster than you can judge them, a faster approval button makes it worse. Two things actually help: scope tasks so there are fewer decision points, and make each decision reviewable in context: you can judge "may I run this migration?" when you can see the migration, and not otherwise.

Reviewing from somewhere else

Vendor remotes. Claude Code's /rc and Codex in the ChatGPT app both put one agent's conversation on your phone. Official and simple; limited to that vendor, and to the chat rather than the machine.

SSH and tmux. Any terminal, from anywhere, if you have a terminal app on the phone and the session was started detachable. Free and robust; a phone keyboard remains a poor fit for a TUI, and you see the terminal only.

Streaming the machine. What we build (reminal, disclosed). The session stays on hardware you own and any browser attaches to it, so you can read the terminal, see the window the agent is driving, and answer the prompt from whatever device is nearby. Needs the host to be running.

What to check before you approve

PromptWhat to look at
"May I run this command?"the command itself, and what directory it runs in
"May I run this migration?"the migration file, and whether it is reversible
"May I push?"the diff and the branch, not the commit message
"May I install X?"whether it is a real package and who publishes it
Anything at all, repeatedlywhether the task was scoped too broadly to begin with

Common questions

How do I review what an AI agent actually did?

Three layers, and most people only use the first. The diff tells you what changed. The transcript tells you why and what it tried. Watching it live tells you what it is about to do, which is the only one that lets you stop a bad decision before it lands.

How do I approve an agent's permission prompt remotely?

You need a channel that carries the prompt to you and a keystroke back. Claude Code's remote control does this for its own session; a tmux session over SSH does it for any terminal; browser-based streaming does it without installing anything on the device you are holding.

What is approval fatigue and how do I avoid it?

Approving everything without reading it, because the prompts arrive faster than you can judge them. The fix is not a faster approval button. It is scoping tasks so there are fewer decisions, and making the ones that remain reviewable in context rather than as a yes/no in isolation.

Should I read the whole transcript?

Usually not. Read the diff first, then search the transcript for the parts that explain anything surprising in it. A transcript read end to end costs more attention than the run saved.
