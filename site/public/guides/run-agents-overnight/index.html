Running AI agents overnight: how to keep them alive and know what happened

A long agent run has two failure modes that have nothing to do with the model: the process dies while you are not looking, and you come back with no idea what happened in between. They need different fixes.

Problem 1: the run does not survive

Three things kill overnight runs, in rough order of frequency.

Your SSH client drops. The shell gets SIGHUP and anything not in a detachable session dies with it. Fix: start every agent inside tmux (or screen, or shpool if you want something lighter). This is the highest-value habit on the page and it is free.

The machine suspends. A laptop shut or idle will sleep, and the agent stops with it. If the work matters, run it on something that stays on (a desktop, a Mac mini, a spare box) or change the machine's sleep behaviour deliberately rather than hoping.

Usage limits. Worth saying because it is common and nothing technical prevents it: a long unattended run can simply exhaust its quota and stop. Scope the task and check your plan's limits before leaving it.

Problem 2: you cannot see what happened

Surviving is not the same as useful. If the agent stopped four hours in to ask "may I run this migration?", a session that stayed alive did not help you.

Two shapes of answer. Notifications tell you something happened: hooks on completion, a webhook, a push. Reachability lets you look and respond. You generally want both, and most setups have only the first.

The options, honestly

Rented box + tmux + Tailscale. The common stack, and it works. You pay monthly, you keep a second environment in sync, and your credentials live on someone else's hardware. Reaching it from a phone still means a terminal app.

Vendor remotes. Claude Code's /rc and Codex in the ChatGPT app both give you one agent's conversation from a phone. Simple, official, limited to that vendor and to the chat rather than the machine.

Keep it on your own machine and make it reachable. This is what we build (reminal, disclosed). The session stays where it is and any browser attaches to it, so you watch the terminal and the windows, and answer from wherever you are. No rent, no second environment. It needs the host to be running, which is the honest cost.

Common questions

Will my agent keep running if I close my laptop?

Not by default. A laptop suspends when you shut it, and the agent process stops with it. The reliable options are to run agents on a machine that stays on, or to change the sleep behaviour on the laptop before you rely on it.

How do I stop an SSH disconnect from killing a long agent run?

Start the agent inside a detachable session: tmux, screen or shpool. Your SSH client dropping then sends SIGHUP to the client, not to the agent, and you reattach later with the session intact. This is the single highest-value habit for long runs.

Should I run agents on a cloud box or my own machine?

A rented box is simpler to keep online and easy to resize. Your own machine costs nothing per month, keeps your credentials and code on hardware you control, and avoids maintaining a second environment in sync. The honest trade is uptime and convenience against rent and data location.

How do I know when an overnight run finished or got stuck?

You need either notifications or a way to look. Hooks that fire on completion cover the first. For the second you need the session reachable from wherever you are, which is what remote access is for.
