How to check on Claude Code from your phone — every method, honest

Agents run long enough now that whoever started the job is usually not sitting there for most of it. The moment you walk away you lose the thread: the agent is still working, but you cannot see what it is doing, answer it when it stops to ask permission, or take over when it goes the wrong way.

There are four honest answers, and they solve different amounts of the problem. This covers all of them, including where ours is the wrong choice.

Method 1: Claude Code remote control (built in, free)

From an active session run /rc (or claude remote-control) and scan the QR with the Claude app. You get that session's conversation on your phone, with the same files and MCP servers.

Good: zero setup, official, no third party. Limits: one agent's chat, not the terminal it runs in and not the other windows on the machine — the dev server it just broke, the browser it is driving, the tests in the next pane.

Method 2: Codex in the ChatGPT app

The equivalent for Codex: pairing lives in the ChatGPT app, signed in.

Good: official, no setup. Limits: the same shape as above, and it covers only Codex. Run agents from two vendors and you now have two apps and two mental models.

Method 3: SSH over Tailscale, with tmux

The stack most people land on: an always-on box, Tailscale to reach it from anywhere, and every agent started inside tmux so the session survives your client dropping. Add Termux on Android or Blink on iOS and you have a real terminal in your pocket.

Good: free, robust, vendor-neutral, and the session genuinely survives a network blip. Limits: two. A phone keyboard is a poor fit for a TUI — arrow keys, Ctrl-C and Esc are all awkward, and the layout reflows when you rotate. And it is terminal only: if the agent opened a browser or a simulator, you cannot see it.

Method 4: stream the machine into a browser (reminal — ours, disclosed)

Disclosure: we build reminal, so weigh this accordingly.

The session stays on a machine you already own and any browser attaches to it. You get the terminal with true colour and scrollback search, and the actual GUI windows with real input, so you can watch the browser an agent is driving and click in it yourself. Nothing to install on the device you are holding, which means a borrowed laptop or a work phone works.

It also ships an MCP server, so agents can read and drive each other's sessions across machines — useful when the tools come from different vendors.

Limits, honestly: it needs the host machine to be running, it is a younger project than the alternatives, and if all you want is one agent's chat then /rc is simpler and you should use that.

Which one to pick

One agent, and you only want its chat: use /rc. It is built in and it is enough.

Already comfortable with tmux and you live in terminals: SSH over Tailscale is free and hard to beat.

Agents from more than one vendor, or you need the windows and not just the shell, or you want to answer from a device you did not set up: that is where streaming the machine earns its place.

Common questions

Can I use Claude Code from my phone?

Yes, several ways. Claude Code has built-in remote control: run /rc in an active session and scan the QR with the Claude app. That gives you the conversation for that one session. If you want the terminal itself, or the other windows on the machine, you need either an SSH client such as Termux or Blink over a private network like Tailscale, or a tool that streams the machine into a browser.

How do I answer an agent's permission prompt when I am away from my desk?

You need something that both shows you the prompt and lets you send a keystroke back. Claude's remote control does this for its own session. A tmux session over SSH does it for any terminal, provided you have a terminal app on the phone. Browser-based streaming does it without installing anything on the phone.

Does the machine need to stay running for this to work?

Yes. Any approach that reaches back to your own hardware needs that hardware to still be running. On a desktop or a Mac mini this is not a problem. On a laptop, check your sleep settings before relying on it overnight.

Is there a way to do this without installing an app on my phone?

Browser-based tools are the only category that avoids it. SSH needs a terminal client, and the vendor remotes need their own app. If you want to use a borrowed device or a work laptop, a browser is the only thing you can assume is already there.
